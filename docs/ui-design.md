# AppManager UI 设计文档 v1.0

## 1. 设计目标

AppManager 的界面应该像一个精致、轻快、可靠的 Windows 11 桌面软件。

它需要让用户一眼知道：

- 当前有哪些分类
- 常用软件在哪里
- 如何快速搜索和启动软件
- 如何扫描软件库
- 如何新增分类

整体观感避免工业上位机式的硬边框、密集表格、灰色控件堆叠和过度信息暴露。第一版不追求复杂炫技，重点是干净、舒服、顺手。

## 2. 视觉关键词

- 轻盈
- 柔和
- 清晰
- 有层次
- 高效率
- Windows 11 风格

## 3. 色彩方案

第一版采用浅色主题。

推荐色彩：

```text
窗口背景：#F5F7FB
主内容背景：#FFFFFF
侧边栏背景：#EEF3FA
主文字：#1F2937
次级文字：#6B7280
弱提示文字：#9CA3AF
主色：#3B82F6
主色悬停：#2563EB
成功色：#10B981
警告色：#F59E0B
危险色：#EF4444
边框色：#E5E7EB
卡片阴影：rgba(15, 23, 42, 0.08)
```

说明：

- 不使用大面积深蓝、灰黑或单调蓝灰背景
- 主色只用于选中、按钮、焦点和少量强调
- 内容区域以白色卡片和浅背景形成柔和层次

## 4. 字体与尺寸

推荐字体：

```text
Segoe UI, Microsoft YaHei UI, Microsoft YaHei, sans-serif
```

字号建议：

```text
应用标题：20px / 600
页面标题：22px / 650
分类导航：14px / 500
软件名称：14px / 600
辅助信息：12px / 400
按钮文字：13px / 500
```

界面不使用夸张大标题，避免像营销页。它应该是工具软件，但视觉上要精致。

## 5. 主窗口布局

推荐窗口最小尺寸：

```text
宽度：1100px
高度：720px
```

主布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 标题栏 / 窗口操作区                                            │
├─────────────────┬────────────────────────────────────────────┤
│                 │ 顶部工具栏                                  │
│ 左侧导航         ├────────────────────────────────────────────┤
│                 │                                            │
│                 │ 主内容区                                    │
│                 │                                            │
└─────────────────┴────────────────────────────────────────────┘
```

区域尺寸：

```text
左侧导航宽度：236px
顶部工具栏高度：76px
内容区内边距：24px
卡片间距：16px
圆角：10px - 16px
```

## 6. 左侧导航

左侧导航用于分类切换和新建分类。

结构：

```text
AppManager

常用软件
全部软件

分类
  办公软件
  开发工具
  设计工具

+ 新建分类
```

设计要求：

- 当前选中的导航项使用浅蓝底色和左侧短色条
- 分类数量较多时支持滚动
- 新建分类按钮放在分类列表底部，视觉上轻但清楚
- 左侧不要做成密集树形控件，避免沉重感

导航项状态：

- 默认
- 悬停
- 选中
- 禁用或加载中

## 7. 顶部工具栏

顶部工具栏承担搜索和全局操作。

结构：

```text
左侧：当前页面标题 / 当前分类名称
中间：搜索框
右侧：扫描按钮、设置按钮
```

搜索框设计：

- 圆角胶囊形
- 宽度约 320px - 420px
- 左侧搜索图标
- placeholder：搜索软件、分类或备注
- 输入时实时过滤

按钮设计：

- 扫描按钮使用主色按钮
- 设置使用图标按钮
- 不在顶部堆放太多操作

## 8. 主内容区

主内容区根据当前导航显示不同内容。

### 8.1 常用软件页

默认首页建议显示“常用软件”。

内容包括：

- 用户收藏的软件
- 最近启动的软件区域可以后续加入

如果没有收藏：

```text
还没有常用软件
把经常使用的软件标记为收藏后，它们会显示在这里。
```

空状态需要有轻量插图或图标，但不要占用过多空间。

### 8.2 全部软件页

显示所有已扫描或手动添加的软件。

建议顶部显示简单统计：

```text
全部软件  24 个应用
```

软件以卡片网格展示。

### 8.3 分类页

显示当前分类下的软件。

页面顶部显示：

```text
开发工具  8 个应用
```

右侧可以有“扫描此分类”操作。

## 9. 软件卡片

软件卡片是界面的核心视觉元素。

推荐尺寸：

```text
宽度：156px - 180px
高度：148px
圆角：16px
```

卡片内容：

```text
┌────────────────────┐
│              ☆     │
│       图标          │
│                    │
│     软件名称        │
│     分类/备注       │
└────────────────────┘
```

视觉要求：

- 卡片白底
- 轻微阴影
- 悬停时微微上浮或增强阴影
- 图标区域居中
- 软件名最多两行，超出省略
- 收藏按钮放右上角，使用星标图标

卡片交互：

- 单击卡片：启动软件
- 右键卡片：打开上下文菜单
- 点击星标：收藏/取消收藏

右键菜单：

- 打开
- 打开所在目录
- 编辑信息
- 从列表移除

## 10. 扫描体验

扫描不应该阻塞界面。

扫描状态建议：

- 顶部按钮进入加载状态
- 内容区显示轻量进度提示
- 扫描完成后弹出简洁提示

扫描结果需要处理：

- 自动识别成功
- 多个 `.exe` 需要选择主程序
- 未找到 `.exe`

多个 `.exe` 的选择窗口：

```text
选择启动程序

检测到多个可执行文件，请选择这个软件的主程序。

[程序列表]

取消    确认
```

## 11. 新建分类弹窗

弹窗应保持简单。

内容：

```text
新建分类

分类名称
[ 输入框 ]

取消    创建
```

规则：

- 分类名不能为空
- 不能与已有分类重名
- 不允许 Windows 文件夹非法字符
- 创建后自动在 `Apps` 下生成对应文件夹

## 12. 删除分类弹窗

删除分类是高风险操作，需要明确。

内容：

```text
删除分类

确定要删除“开发工具”吗？

将删除的文件夹：
AppManager/Apps/开发工具

[x] 同时删除真实文件夹和其中的软件文件

取消    删除
```

设计要求：

- 复选框默认选中
- 删除按钮使用危险色
- 路径必须清晰展示
- 如果真实文件夹不存在，文案需要说明只删除分类记录

## 13. 设置页

第一版设置页保持简洁。

设置项：

- 软件库路径，只读展示
- 打开软件库目录
- 主题：浅色
- 关于 AppManager

后续再加入：

- 深色主题
- 托盘运行
- 全局快捷键
- 备份与恢复

## 14. 空状态设计

空状态必须友好，但不啰嗦。

常见空状态：

- 没有分类
- 分类中没有软件
- 搜索无结果
- 扫描未发现软件

示例：

```text
这里还没有软件
把软件文件夹放入这个分类，然后点击扫描。

[扫描此分类]
```

## 15. 动效与流畅性

动效原则：

- 快
- 轻
- 不抢眼

建议：

- 卡片悬停：120ms
- 页面切换：150ms 淡入
- 按钮反馈：100ms
- 弹窗出现：120ms 缩放 + 淡入

不要使用复杂长动画。

## 16. UI 原型阶段交付内容

在功能实现前，先完成以下 UI 文件：

1. 主窗口静态界面
2. 左侧导航
3. 顶部搜索与工具栏
4. 软件卡片网格
5. 常用软件空状态
6. 新建分类弹窗样式
7. 删除分类弹窗样式
8. 设置页静态样式

UI 阶段只做界面展示和基础前端状态，不接入真实扫描、文件读写和启动软件功能。

## 17. 待用户确认

以下内容已确认：

1. 首页默认显示“常用软件”
2. 软件卡片支持“舒适网格”和“紧凑网格”切换
3. 左侧导航固定 `236px` 宽
4. 第一版 UI 阶段需要设置页静态界面
5. 技术路线接受 Tauri

## 18. UI 阶段实施约束

当前阶段只编写 UI 和静态交互：

- 可以使用假数据展示软件卡片
- 可以实现分类切换、搜索过滤、网格密度切换、弹窗开关等前端状态
- 不实现真实文件扫描
- 不实现真实文件夹创建、删除
- 不实现真实软件启动
- 不写入真实软件库目录

待用户确认 UI 满意后，再进入功能实现阶段。
