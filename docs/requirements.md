# AppManager 需求文档 v1.0

## 1. 项目定位

AppManager 是一个面向 Windows 11 的桌面窗口软件，用于集中管理本机软件目录、分类、扫描和启动应用程序。

它的核心目标不是替代应用商店，也不是做系统清理工具，而是成为一个本地软件启动中心和软件目录管理工具，帮助用户减少查找软件、打开软件、整理软件文件夹的时间。

## 2. 目标用户

- 希望统一整理 Windows 软件的人
- 经常使用绿色软件、便携软件或独立软件文件夹的人
- 希望通过一个入口快速启动工作软件的人
- 希望按照用途分类管理软件的人

## 3. 设计原则

- 优先保证流畅、稳定、清晰
- UI 风格贴近 Windows 11，简洁、现代、有质感
- 第一阶段不做过重功能，先把分类、扫描、启动做好
- 所有新增想法在实现前需要用户确认
- 功能实现必须在需求文档和 UI 确认后再开始

## 4. 应用形态

- 软件类型：Windows 11 桌面窗口软件
- 数据存储：本地配置文件
- 软件名称：AppManager
- 软件根目录：APP 首次启动时在 APP 目录下自动创建一个新的软件库目录

推荐目录结构：

```text
AppManager/
  Apps/
    办公软件/
    开发工具/
    设计工具/
  config/
    app-data.json
```

说明：

- APP 首次启动时自动创建软件库目录
- 分类会在 `Apps` 目录下创建真实文件夹
- 软件配置、分类信息、启动路径、收藏信息保存在本地配置文件中
- 这样便于迁移、备份，也方便用户把绿色软件或便携软件集中放入软件库

## 5. 核心功能

### 5.1 分类管理

用户可以创建、重命名、删除分类。

每个分类对应软件库目录中的一个真实文件夹。

示例：

```text
Apps/
  办公软件/
  开发工具/
  设计工具/
```

分类信息包括：

- 分类名称
- 分类文件夹路径
- 排序位置
- 创建时间
- 更新时间

删除分类时需要谨慎处理：

- 删除分类时弹窗询问是否删除真实文件夹
- 默认选项为删除真实文件夹
- 如果用户取消删除真实文件夹，则只删除 AppManager 中的分类记录
- 删除真实文件夹属于高风险操作，弹窗需要清晰展示将被删除的文件夹路径

### 5.2 软件目录管理

用户可以把其他软件文件夹放到某个分类文件夹中。

示例：

```text
Apps/
  开发工具/
    VSCode/
    Git/
    Python/
```

AppManager 可以扫描分类目录下的软件文件夹，并尝试识别可启动程序。

### 5.3 软件扫描

扫描方式：

- 扫描全部分类
- 扫描单个分类
- 扫描单个软件文件夹

基础识别规则：

- 如果软件文件夹内只有一个主要 `.exe` 文件，自动设为启动程序
- 如果存在多个 `.exe` 文件，提示用户选择主程序
- 如果没有 `.exe` 文件，标记为无法启动，需要用户手动处理

软件信息包括：

- 软件名称
- 所属分类
- 软件文件夹路径
- 启动程序路径
- 图标
- 是否收藏
- 最近启动时间
- 启动次数
- 备注

### 5.4 软件启动

用户可以在 AppManager 中直接启动软件。

第一版支持：

- 点击软件卡片启动
- 右键打开软件所在目录
- 显示启动失败提示

后续可选增强：

- 以管理员身份运行
- 启动参数
- 快捷键启动
- 启动前检查路径是否存在

### 5.5 搜索

第一版加入搜索功能。

搜索范围：

- 软件名称
- 分类名称
- 备注

搜索体验目标：

- 输入时实时过滤
- 支持从搜索结果中直接启动软件
- 搜索框始终处于界面上方显眼位置

### 5.6 常用软件

第一版加入常用软件功能。

常用软件来源：

- 用户手动收藏
- 根据启动次数和最近启动时间显示推荐常用软件

第一版建议优先实现“手动收藏”，自动推荐可作为后续功能。

- 保持足够留白、圆角、柔和阴影、清晰层级
- 避免过度密集的表格、硬边框、大面积灰底和机械式控件堆叠
- 动效克制，优先保证流畅
- 软件卡片清晰展示图标和名称

## 7. 数据存储

第一版使用本地 JSON 配置文件。

推荐文件：

```text
config/app-data.json
```

基础结构示例：

```json
{
  "libraryPath": "D:/AppLibrary",
  "categories": [],
  "apps": [],
  "settings": {
    "theme": "light",
    "startupView": "favorites"
  }
}
```

后续如果数据复杂，可以再迁移到 SQLite。

## 10. 服务端/客户端模式需求草案

此功能属于新增架构能力，用户已确认采用该方向，并要求分阶段推进。

### 10.1 功能定位

AppManager 后续可以支持两种运行模式：

1. 本地模式
2. 网络模式

本地模式：

- 当前已有模式
- 软件库位于本机 `AppManager.exe` 同目录下的 `AppManagerLibrary`
- 所有分类、扫描、启动、编辑和删除都只操作本机

网络模式：

- AppManager 可以切换为服务端或客户端
- 服务端负责提供软件库共享能力
- 客户端可以连接服务端，查看服务端软件库，并下载软件到本机对应分类目录

### 10.2 运行角色

设置中增加“运行模式”配置：

```text
运行模式：
  本地模式
  服务端模式
  客户端模式
```

建议：

- 第一版默认仍然使用本地模式
- 服务端和客户端功能需要用户主动开启
- 切换模式后提示是否需要重启应用或重启网络服务

### 10.3 服务端模式

服务端模式提供软件库访问能力。

服务端设置项：

- 是否启用服务端
- 监听地址
- 监听端口
- 服务端名称
- 是否允许客户端下载软件
- 是否允许客户端查看软件列表
- 是否启用账号密码认证
- 服务端管理员用户名
- 服务端管理员密码
- 访问令牌
- 开机自启服务端

默认建议：

```text
监听地址：0.0.0.0
监听端口：8765
访问控制：需要用户名 + 密码，后续可增加访问令牌
允许下载：开启
允许远程删除：关闭
允许远程修改：关闭
```

服务端提供的数据：

- 分类列表
- 软件列表
- 软件名称
- 软件描述
- 软件图标
- 软件大小
- 软件版本或备注
- 软件所在分类
- 是否可下载

服务端提供的能力：

- 查询服务端信息
- 获取分类列表
- 获取软件列表
- 下载指定软件
- 查看软件元数据

第一版不建议提供：

- 远程删除服务端软件
- 远程修改服务端软件信息
- 远程启动服务端软件
- 多用户权限系统

原因：

- 这些功能安全风险更高
- 当前核心需求是“共享和下载软件库”
- 先保证传输稳定和文件完整性更重要

### 10.4 客户端模式

客户端模式用于连接服务端并下载软件。

客户端设置项：

- 服务端地址
- 服务端端口
- 连接协议
- 用户名
- 密码
- 访问令牌
- 连接测试
- 下载目标策略
- 开机自启客户端

服务端连接方式：

```text
IP 地址：192.168.1.10
域名：apps.example.com
端口：8765
```

客户端能力：

- 连接服务端
- 查看服务端软件分类
- 搜索服务端软件
- 查看服务端软件详情
- 下载软件到本机软件库
- 下载后自动放入对应分类文件夹
- 下载完成后自动扫描并添加到本机 AppManager

下载目录规则：

```text
本机 AppManagerLibrary/
  Apps/
    服务端分类名/
      软件文件夹或软件文件
```

如果本机不存在对应分类：

- 自动创建分类
- 或弹窗询问是否创建

建议第一版采用自动创建，减少操作步骤。

### 10.5 软件下载规则

服务端软件可能存在两种形式：

1. 单个 `.exe`
2. 软件文件夹

下载规则：

- 单个 `.exe` 下载到对应分类目录
- 软件文件夹打包后下载，客户端解压到对应分类目录
- 下载完成后校验文件大小或哈希
- 下载失败时保留 `.partial` 临时文件或自动清理
- 下载过程中显示进度
- 下载完成后提示用户

建议：

- 服务端发送前对软件文件夹进行 zip 打包
- 客户端下载后自动解压
- 软件库内部避免直接传输裸目录，便于断点、校验和跨机器传输

### 10.6 安全建议

由于服务端会暴露软件下载能力，需要基础安全设计。

第一版建议必须支持：

- 用户名和密码认证
- 密码本地加密或哈希保存，不明文保存
- 客户端连接时输入用户名和密码
- 可选访问令牌，用于后续免输入或自动连接
- 默认只监听局域网
- 默认不允许远程删除
- 默认不允许远程修改
- 服务端显示当前监听地址和端口
- 客户端连接失败时显示明确原因

后续可选：

- HTTPS
- 访问白名单
- 下载日志
- 多用户账号
- 权限分组

### 10.7 开机自启

设置中增加开机自启功能。

可配置项：

- AppManager 开机自启
- 以本地模式启动
- 以服务端模式启动
- 以客户端模式启动
- 启动后最小化

第一版建议：

- 只做 AppManager 开机自启
- 是否自动启用服务端由运行模式决定
- 默认不开启
- 用户手动开启后写入 Windows 启动项

  监听端口

  管理员密码
  访问令牌

  服务端地址

当处于本地模式时：

- 服务端设置和客户端设置可以折叠或置灰

当处于服务端模式时：

- 显示服务端状态
- 显示监听地址
- 显示端口
- 显示客户端连接提示

当处于客户端模式时：

- 显示连接状态
- 显示服务端地址
- 显示测试连接按钮

### 10.9 推荐技术方案

考虑当前项目使用 Tauri，推荐：

- 前端继续使用当前 UI
- 后端 Rust 提供本地文件操作和网络服务
- 服务端使用 Rust HTTP 服务
- 客户端使用 HTTP API 连接服务端
- 软件文件夹下载采用 zip 打包传输
- 软件元数据使用 JSON

推荐 API 草案：

```text
GET  /api/server-info
GET  /api/categories
GET  /api/apps
GET  /api/apps/:id
GET  /api/apps/:id/download
POST /api/auth/test
```

第一版不建议使用数据库服务、账号系统或复杂后台进程。

### 10.10 分阶段实现建议

第 1 阶段：设置页和本地开机自启

- 设置页加入运行模式 UI
- 加入开机自启开关
- 保存设置到本地配置
- 不启动真实网络服务

第 2 阶段：服务端只读共享

- 服务端监听端口
- 提供分类和软件列表
- 提供图标和元数据
- 支持用户名和密码认证
- 可选支持访问令牌

第 3 阶段：客户端下载

- 客户端连接服务端
- 查看服务端软件库
- 下载单个 `.exe`
- 下载完成后自动扫描

第 4 阶段：软件文件夹下载

- 服务端 zip 打包软件文件夹
- 客户端下载并解压
- 显示下载进度和错误提示

第 5 阶段：体验增强

- 下载队列
- 下载日志
- 断点续传
- 服务端访问日志
- HTTPS 或局域网信任机制
